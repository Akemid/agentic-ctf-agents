### Q1 Porting shape
Recommendation: one invocation = one character (one MCP session = one join_match). Payload (top-level JSON object; also accept {"prompt": "<json string>"} because agentcore invoke wraps text in prompt [UNVERIFIED]): match_id (req), name (req-ish; default f"{runtime}-{agent_index}", sanitize [a-z0-9_-]{1,32}), team (red|blue|auto, default auto=red then blue), agent_index, model alias (haiku|opus|nova-lite), window (sdk/strand_decider), threshold/threat_threshold/llm_budget_ms/safety_margin_ms (decider_loop), mode (async|stream). Reject non-dict, non-str prompt, unknown model; never accept caller message history (AGENTS.md invariant 5).
Execution model options:
 A) Async start (RECOMMENDED): entrypoint validates, starts match in a background thread guarded by add_async_task/complete_async_task (finally), returns {"status":"started",...} immediately; second invocation on SAME session id with {"action":"status"|"stop"} returns state (same microVM). Session stays HealthyBusy until match_over; async max 8h, max session 8h, idle 15m only when Healthy. Double-start guard needed. Logs in CloudWatch.
 B) Sync blocking: simple, but 15 min sync request timeout.
 C) Streaming generator of tick logs: live demo value, but 60 min streaming cap and unclear behavior on client disconnect.
Port changes: drop argparse/main/os._exit/exit_if_threads_linger/sys.path hacks; replace fcntl DECIDER_LOCK_FILE (cross-process lock is meaningless across microVMs; serialization moves to SageMaker adapter); print->logger; harness session/memory dirs -> /tmp/.agent/* [writable fs UNVERIFIED]; MCP via explicit MCPClient(lambda: streamablehttp_client(url, headers={"Authorization": f"Bearer {token}"})) instead of MCPClient.load_servers(config); decider_down flag is permanent after first failure in original -> consider circuit breaker with cooldown (transient SageMaker throttles); per-call decider timeout clamped to tick deadline (original 120s).
Quota facts (https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/bedrock-agentcore-limits.html): sync request timeout 15 min; streaming 60 min; async job 8 h; max session 8 h (maxLifetime 60..28800 s), idle default 15 min (idleRuntimeSessionTimeout 60..28800); payload 100 MB; new sessions 25/s; CodeZip 250 MB zipped/750 MB unzipped; 2 vCPU/8 GB per session; OAuth2 credential providers quota 50. Long-running doc: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-long-run.html (do not block /ping; use threads/async).
Set lifecycleConfiguration explicitly (e.g. idle 900, maxLifetime ~4-5 h) to cap runaway cost; StopRuntimeSession to kill.

### Q2 Shared code packaging
Fact: CLI manual flow equivalent is `uv pip install --python-platform aarch64-manylinux2014 --python-version 3.x --target=... --only-binary=:all: -r pyproject.toml` then copy code into zip root (https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-code-deploy-python.html). `-r pyproject.toml` installs declared deps only; relative path deps / [tool.uv.sources] are not honored and --only-binary rejects source dirs. Whether CLI follows path deps is [UNVERIFIED] (no CLI source available locally); evidence from staging suggests it copies only codeLocation.
Options: (1) duplicate per runtime: zero tooling, 4x drift (violates rule of three: harness_sdk module used by 3, _client by 2). (2) Source-of-truth `shared/ctf_common/` + sync/vendor script copying into app/<rt>/ctf_common/ before package/deploy, drift check in CI (RECOMMENDED; works with CodeZip as-is; tests run on shared/). (3) uv workspace/path dep: high risk with CodeZip. (4) Switch to Container build with buildContextPath=repo root: robust for shared dirs but ARM64 CodeBuild, 4 Dockerfiles, slower deploy. (5) private index: overkill. Keep tests/ outside codeLocation to avoid zipping them. Shared third-party deps must still be declared in each runtime pyproject.

### Q4 SageMaker adapter
Contract (https://docs.aws.amazon.com/sagemaker/latest/dg/your-algorithms-inference-code.html): container runs as `docker run image serve` (exec-form ENTRYPOINT, root user), listens 8080, POST /invocations, GET /ping (2 s timeout, must be 200 within 8 min of start or CreateEndpoint fails; ping failures cause instance replacement), accept socket in 250 ms, respond within 60 s, model artifacts in read-only /opt/ml/model; do not bundle NVIDIA drivers.
Model: StrandsAgents/strands-decider-2B-hobson-v21 = Qwen/Qwen3.5-2B-Base + LoRA adapter + readout head, Apache-2.0, `pip install strands-decider`, base weights download from Hub on first use, serve binds 127.0.0.1 no auth (https://huggingface.co/StrandsAgents/strands-decider-2B-hobson-v21). Size/latency not stated. T4 has no native bf16 [dtype risk UNVERIFIED].
Design (RECOMMENDED): adapter = FastAPI/uvicorn on 8080 supervising `strands-decider serve` as subprocess on 127.0.0.1; POST /invocations body == /v1/systemone request ({state, model, questions}) forwarded 1:1, response == upstream JSON plus additive `adapter:{queue_wait_ms}`; global FIFO asyncio.Lock (bounded wait, e.g. 503 after N s so callers fall back to LLM); inference never blocks /ping (async handler, upstream via httpx); /ping = 200 only after upstream /health OK AND a warm-up question completed; if upstream dies -> /ping 503 (SageMaker replaces instance) with one auto-restart attempt. Alternative: import strands-decider in-process (saves a hop but internal API unverified).
Image: bake base+adapter weights at build (snapshot_download, HF_HUB_OFFLINE=1 at runtime) vs S3 ModelDataUrl/S3DataSource uncompressed (docs recommend for large models) vs download at startup (HF outage/rate-limit risk during workshop; rejected). Base image: AWS PyTorch inference DLC or pytorch/pytorch CUDA runtime; must be linux/amd64 (laptop is Apple Silicon -> emulated build slow; consider CodeBuild); CUDA version must be compatible with host driver [UNVERIFIED]. Use L1 CfnModel/CfnEndpointConfig/CfnEndpoint (L2 is alpha package; avoid), fixed endpoint name (e.g. ctf-decider) so IAM/env values survive destroy/recreate; set container startup health-check timeout in variant if load+warmup may exceed 8 min [property name ContainerStartupHealthCheckTimeoutInSeconds UNVERIFIED].
Layout/stack placement: separate CDK app `infra/decider/` (own cdk.json/package.json/jest) + adapter source `infra/decider/adapter/` (or decider-adapter/). REJECT extra stack in agentcore/cdk/bin/cdk.ts: file is CLI-scaffolded, and whether `agentcore deploy` deploys only AgentCore-<project>-<target> or all app stacks is UNDOCUMENTED (https://github.com/aws/agentcore-cli docs say only "Deploy infrastructure to AWS"); if it deploys all, every agent deploy would silently start a ~$0.736/h endpoint. Budget alert must live outside DeciderStack (destroyed weekly).
Latency vs 4.5 s: unknown; needs benchmark. With serialization, per-tick queue = N_decider_chars x L; need L <~ 1 s for 3 chars. Client: boto3 sagemaker-runtime invoke_endpoint, Config(read_timeout~3 s, connect_timeout~1 s, retries max 1) [tune]; add ~tens of ms internet hop (PUBLIC runtime). Quota ml.g4dn.xlarge for endpoint usage often 0 -> request early. Region us-east-2 supports AgentCore Runtime + Identity (https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agentcore-regions.html).

### Q5 AgentCore Identity wiring
KEY FINDING: agentcore.json OAuthCredential has no clientId/clientSecret/secretArn. Per CLI docs (https://github.com/aws/agentcore-cli/blob/main/docs/configuration.md) client id/secret come from agentcore/.env.local (pattern AGENTCORE_CREDENTIAL_{projectName}{credentialName}_CLIENT_ID/_CLIENT_SECRET; exact normalization of hyphens/underscores UNVERIFIED) and the page says nothing about Secrets Manager references. The control-plane API supports clientSecretConfig/EXTERNAL Secrets Manager (console doc: https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity-add-oauth-client-custom.html) but CFN CustomOauth2ProviderConfigInput lists only ClientId/ClientSecret/OauthDiscovery (ClientSecretArn is an output) (https://docs.aws.eu/AWSCloudFormation/latest/TemplateReference/aws-properties-bedrockagentcore-oauth2credentialprovider-customoauth2providerconfiginput.html). So "external Secrets Manager secret" from D5 is likely NOT expressible through the CLI schema.
Options: A) 4 OAuthCredential entries (name, discoveryUrl=https://cognito-idp.us-east-2.amazonaws.com/<pool>/.well-known/openid-configuration, scopes ["agentic-ctf/mcp"], vendor CustomOauth2, usage outbound) + a hydrate script that reads SSM client-id + Secrets Manager secret and writes gitignored agentcore/.env.local before `agentcore deploy` (secret transits laptop; simplest, CLI-native). B) Create providers in cdk-stack.ts with CfnOAuth2CredentialProvider (if present in aws-cdk-lib 2.261 [UNVERIFIED]) using SecretValue.secretsManager('agentic-ctf/agents/<n>', {jsonField}) dynamic references: no secret on laptop, but bypasses agentcore.json credentials[] (CLI status/deployed-state blind to them) and needs own ARN wiring. C) Out-of-band create via boto3 create_oauth2_credential_provider with clientSecretSource EXTERNAL: exact API, but outside IaC. Recommend A for first slice with B as documented fallback; spike S3 decides.
IAM for each runtime role (CDK addToPrincipalPolicy), least privilege: bedrock-agentcore:GetResourceOauth2Token on token-vault/default, token-vault/default/oauth2credentialprovider/<provider>, workload-identity-directory/default, workload-identity-directory/default/workload-identity/<runtime>-* (resource types confirmed via service authorization reference https://docs.aws.amazon.com/service-authorization/latest/reference/list_amazonbedrockagentcore.html; exact ARN format by analogy with payments example in amazon-bedrock skill). GetWorkloadAccessToken* not needed for runtimes created after 2025-10-13 (service-linked role AWSServiceRoleForBedrockAgentCoreRuntimeIdentity; https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-oauth.html) -> deployer needs iam:CreateServiceLinkedRole. secretsmanager:GetSecretValue on the Identity-managed secret `bedrock-agentcore-identity!default/oauth2/<provider>-*` [UNVERIFIED, likely]; NOT on agentic-ctf/agents/* (runtime never reads those). sagemaker:InvokeEndpoint on arn:aws:sagemaker:us-east-2:<acct>:endpoint/ctf-decider (decider runtimes only). ssm:GetParameter on /agentic-ctf/* and /ctf-decider/* if runtime-time lookup. Check first whether the L3 already grants token access for declared credentials (synth + inspect role) [UNVERIFIED].
provider_name wiring: static env var in agentcore.json envVars is enough if the deployed provider name equals credential name; otherwise derive from deployed credentialProviderArn (available in AgentCoreStackProps.credentials) and inject via env.runtime.addEnvironmentVariable. Cross-stack values: MCP URL changes if game stack recreated -> prefer runtime SSM read at session start (resilient) over CDK-time valueForStringParameter (stale until redeploy); endpoint name fixed constant.
